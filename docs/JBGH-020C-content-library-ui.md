# JBGH-020C — Content Library UI + Import Preview / Approval

Status: CLOSED / PASS
Milestone: JBGH-020C — Content Library UI + Import Preview / Approval
Dependencies: JBGH-020A, JBGH-020B

## Objective

Expose the safe content pipeline in the operational dashboard without adding a
client-side escape hatch around scanning, import planning, compatibility,
approval, source hash verification, staging, or provider destination mapping.

```text
Content Library
  -> configured-root source selection
  -> scanner result
  -> backend-generated import preview
  -> explicit approval
  -> backend execution and audit lifecycle
  -> installed inventory
```

## API contract

| Endpoint | Purpose | Safety boundary |
|---|---|---|
| `GET /api/content/sources` | Lists configured-root files/directories | Does not accept client root paths |
| `POST /api/content/scan` | Scans a root-relative `sourcePath` | Rejects paths outside `GAMEHUB_CONTENT_ROOT` |
| `POST /api/content/import-plans` | Creates `ContentImportPlan` from a scanned content ID | Client cannot provide destination/staging path |
| `POST /api/content/import-plans/:operationId/execute` | Executes an existing plan | Requires `{ "approve": true }` |
| `GET /api/content/inventory` | Reads provider-managed installed content | Uses server-side Paper paths |
| `GET /api/content/history` | Reads append-only import audit JSONL | Persists independently of in-memory plans |

The dashboard never sends a destination path, staging path, provider root, or
hash override. It renders the values generated by the backend plan.

## Dashboard behavior

The **CONTENT LIBRARY** panel provides:

- configured source browser;
- scan/classification result with type, size, SHA-256, markers, status badge,
  warnings, and compatibility reason codes;
- non-mutating import-plan preview including provider destination, staging
  location, action sequence, warnings, and blocking reasons;
- an explicit **Approve & install** action only for `planned` plans;
- lifecycle/status feedback derived from scanner events and returned immutable
  import audit entries;
- installed-content inventory; and
- recent import audit history.

Blocked plans remain visible with structured reasons and cannot show an
approval action.

## Persistence behavior

Scanned item and pending-plan state is intentionally process-local because a
source must be scanned again after a service restart before approval. Installed
inventory and append-only import history are read from provider-managed storage
on every dashboard refresh, so they survive backend restart.

## Automated acceptance

`tests/content-library-api.test.ts` verifies:

- configured content-root discovery;
- root traversal rejection;
- Java-world scan, backend-generated import preview, explicit approval, and
  managed installation;
- ignored client-supplied arbitrary destination/staging fields;
- blocked unknown-content plan;
- inventory and audit history after backend restart.

`tests/dashboard-ui.test.tsx` verifies the panel exposes browser, scan,
preview, approval, and audit surfaces while rendering no destination/staging
input controls.

## AI Studio Consumption Guide

AI Studio may summarize scanner results, plans, warnings, status, installed
inventory, and audit history. It must not create approval, destination, staging,
or execution parameters on behalf of the operator.
