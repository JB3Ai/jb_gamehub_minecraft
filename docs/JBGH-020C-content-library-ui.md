# JBGH-020C — Content Library UI + Import Preview / Approval

Status: CLOSED / PASS
Milestone: JBGH-020C — Content Library UI + Import Preview / Approval
Dependencies: JBGH-020A, JBGH-020B

## Objective

Expose the safe content pipeline in the operational dashboard without adding a
client-side escape hatch around scanning, import planning, compatibility,
approval, source hash verification, staging, or provider destination mapping.

```text
Content Library
  -> configured-root source selection
  -> scanner result
  -> backend-generated import preview
  -> explicit approval
  -> backend execution and audit lifecycle
  -> installed inventory
```

## API contract

| Endpoint | Purpose | Safety boundary |
|---|---|---|
| `GET /api/content/sources` | Lists configured-root files/directories | Does not accept client root paths |
| `POST /api/content/scan` | Scans a root-relative `sourcePath` | Rejects paths outside `GAMEHUB_CONTENT_ROOT` |
| `POST /api/content/import-plans` | Creates `ContentImportPlan` from a scanned content ID | Client cannot provide destination/staging path |
| `POST /api/content/import-plans/:operationId/execute` | Executes an existing plan | Requires `{ "approve": true }` |
| `GET /api/content/inventory` | Reads provider-managed installed content | Uses server-side Paper paths |
| `GET /api/content/history` | Reads append-only import audit JSONL | Persists independently of in-memory plans |

The dashboard never sends a destination path, staging path, provider root, or
hash override. It renders the values generated by the backend plan.

## Dashboard behavior

The **CONTENT LIBRARY** panel provides:

- configured source browser and a local scanned-content library with text search
  and All, Worlds, Plugins, Resource Packs, Datapacks, Unsupported, and
  Blocked filters;
- a selectable content-details view with content/manifest IDs, safe source
  label, scan timestamp, type, size, full SHA-256, markers, validation state,
  warnings, compatibility status, and structured reason codes;
- non-mutating import-plan preview including provider destination, staging
  location, action sequence, warnings, and blocking reasons;
- an explicit **Approve & install** action only for `planned` plans;
- lifecycle/status feedback derived from scanner events and returned immutable
  import audit entries;
- installed-content inventory; and
- recent import audit history.

Blocked plans remain visible with structured reasons and cannot show an
approval action.

## Import states and lifecycle

The dashboard renders backend state rather than calculating progress:

- `planned` is **READY FOR APPROVAL**;
- `blocked` is visibly blocked with the backend reason code/message;
- returned audit records identify execution, success, failure, rollback, and
  staging cleanup.

Execution uses the JBGH-020B audit lifecycle, including source verification,
staging, validation, installation, rollback where needed, and cleanup. It does
not invent progress percentages.

## Installed inventory and history

Inventory is provider-derived from Paper-managed worlds, plugins, resource
packs, and world datapack directories. It is not inferred from import logs.
The audit display keeps the immutable action, result, timestamp, and managed
destination visible. Import records cannot be edited or deleted from the UI.

## Persistence behavior

Scanned item and pending-plan state is intentionally process-local because a
source must be scanned again after a service restart before approval. Installed
inventory and append-only import history are read from provider-managed storage
on every dashboard refresh, so they survive backend restart.

## AI Studio Consumption Guide

AI Studio remains read-only. A future bounded content-library context may
summarize scanner results, plans, warnings, status, installed inventory, and
audit history; it must not create approval, destination, staging, or execution
parameters on behalf of the operator. This slice does not expose an AI mutation
endpoint or an AI-controlled import path.

## Known limitations

- Scan results and pending plans are intentionally process-local; a restart
  requires a rescan before new approval. Completed history and provider
  inventory remain rediscoverable after restart.
- The UI supports supported JBGH-020B types only. It displays unsupported
  content and backend blocking reasons but cannot install it.
- Acceptance used only the disposable managed Paper harness and a temporary
  corpus. The temporary source corpus, imported world/plugin, and staging
  artifacts were removed after evidence capture. The immutable harness audit
  retains the actual lifecycle entries.
